# 无障碍人工审计协作工作台

源提示词摘要：审计员记录问题、复现步骤、影响人群和严重程度，审核员判断重复或补充证据，开发人员提交修复，复测人员关闭或重新打开问题；所有核心流程可以用键盘完成，并正确管理焦点和错误提示。

## 技术栈

SolidStart、TypeScript、Park UI、Solid Router、TanStack Query、Solid Store、Modular Forms、Zod、Solid i18n primitives。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62025`

## 可用流程

- 创建审计问题，保存复现步骤、影响人群、证据和严重程度。
- 问题按待分诊、修复中、待复测、已关闭和重新打开流转。
- 将重复问题合并到主问题，保留来源关系和操作审计。
- 开发修复与复测结果分开记录，复测失败自动重新打开。
- 支持跳过导航、可见焦点、读屏提示、`N` 快捷键聚焦新建问题、`Ctrl+Enter` 提交。
- 数据保存在 localStorage，Park UI preset 与 Ark UI 可访问交互原语参与界面实现。

## 离线协作与冲突对账

问题不再整条覆盖，而是按字段带修订号对账（`src/lib/collab.ts`）：

- **修订号**：每条问题有 `rev`，每个字段值记录写入时的修订号、修改人和时间。
- **离线批次**：断网修改按原记录修订号 `baseRev` 排队到 outbox；同一字段的连续修改在未推送批次内就地合并，不产生重复条目。
- **字段级冲突**：同一字段在 `baseRev` 之后被不同人改过，后到内容不会覆盖当前版本，而是进入该字段的待审版本列表；审核员在详情页显式裁决（保留当前 / 采纳待审版本）。其他字段各自正常生效。
- **失败保留与重试**：网络恢复推送时，若某一步（如重复合并）失败，批次保留在本地并记录 `appliedCount`，修复后可原样重试；每个操作有幂等键 `opId`，已写入的修改和操作时间线重试时不会重复追加。
- **重复合并归并**：合并后旧记录成为主问题的别名（`aliases`），旧链接经 `resolveId` 解析到主记录；重复项的时间线与后续编辑都归到同一主记录视图。
- 顶部工具栏可切换审核员、模拟断网/恢复、注入一次同步故障来演示失败保留与重试。
